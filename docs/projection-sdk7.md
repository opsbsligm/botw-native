# SDK7 1.6.0 投影接入与功能门禁

本适配只接受 `legacy_sdk7.PINS` 的三个原始模块。原始文件指纹、四个完整投影方法的摘要及九条加载指令必须全部一致，才生成宿主投影调用。透视矩阵和第一组视锥加载的寄存器不同于 1.8/1.9，分别使用 SDK7 的 s2/s3、s0/s1；不替换正交投影方法。

静态 Mod 不得改动这四个方法的上下文。补丁准备、AOT 和最终打包仍遵循同一快照，不能把被宿主替换的指令补丁记作生效。生成后的库 ID 变化，运行时和游戏代码库必须配套重建；只更新可执行文件不能获得这些调用。

## 当前边界

- 原始 SDK7 包缺少投影元数据和实际 `rt_persp` 调用。仅保存 FOV 设置不能改变画面。
- 新库必须包含全部九个投影位置，运行时才报告投影链可用。旧库、缺项或位置超出 main 模块时关闭依赖功能。
- SDK7 的菜单、加载与过场状态适配尚未完成。默认保持 16:9 取景，禁用宽屏、TAA 和 FSR3.1，旧 TAA 设置在后端回退到 SMAA；环境变量不能绕过这些依赖检查。
- SDK7 FOV 默认禁用。仅隔离验收时设置 `SAVAGEWIND_SDK7_FOV=1`；该模式不保证过场恢复原视野，侧栏明确显示实验状态。禁止将实验开关写入正式 Steam 启动器。
- FSR1、SMAA、阴影精度与各向异性过滤不依赖这组投影位置，保留各自后端路径。

## 已验证与待验证

远端 Linux 上，原创三模块经生产生成器、Clang 编译并执行九个替换函数，逐项检查目标寄存器及其它寄存器保持不变。完整方法变化、元数据缺项、版本变化及静态 Mod 冲突必须拒绝。

生产 `output_scale.c` 的测试覆盖缺少库、缺少位置、越界位置、SDK7 默认门禁、INI 回退、实验 FOV 的实际数学结果、重复读取不叠加、HUD 相机保持原值以及已有事件检测时恢复原视野。这些是组件验证；真实游戏的视野 A/B、阴影覆盖、菜单与过场、时序效果和性能仍需实机单独验收。`hardware_validated=false`。
