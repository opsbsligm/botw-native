# CA4：静态 Mod 构建与 HD 贴图边界

更新：2026-11-14。本文替代此前将告警阈值视作堆扩容的设计。整体 `hardware_validated=false`。

## 当前实现

- RomFS 覆盖与旧 setup 补丁接口保留在 `runtime/mods.c`；Linux 便携包新增目录FD、社区 `romfs/` 布局、原子视图及失败停止启动，避免依赖不存在的 `extracted` 和静默忽略准备失败。11项定向组件回归通过，完整CI及真实资源覆盖/移除仍需单独实机验收。
- Linux 私有构建新增 `--code-mods`，在 AOT 生成之前处理 `mods/<名称>/exefs/` 中的标准 IPS、IPS32 和 PCHTXT。原始 main/subsdk0/sdk 先核对受管 SDK7 SHA-256，再解压、验证段摘要及补丁。
- 代码生成直接使用补丁后的内存快照，不重新打开活动输入；输出准备目录一次原子发布。生成记录和准备的全部 NSO 纳入 code 阶段逐文件回执。
- 打包重新读取并验证原始模块、活动补丁和准备输出，与生成记录逐字段及逐字节比较。运行包使用相同的补丁后 NSO，确保 rodata/data 变化也能进入运行时；输入变化必须重新生成、编译。
- 保护 MOD0、dynamic、符号与字符串表、重定位表及目标、异常展开记录、宿主 HLE 函数和 SDK7 时钟替换位置。冲突明确失败，不能把会被宿主替换的指令修改记成生效。
- 原始输入只读；保留原始版本门禁，不增加跳过指纹或接受任意版本的选项。完整操作与边界见 [mods.md](mods.md)。

## HD 贴图堆仍未闭合

`tex_pool_mib` / `SAVAGEWIND_MAX_TEXTURE_POOL` 目前只控制 host 纹理池告警阈值，不扩大 guest 堆、不预分配显存、不保证大贴图能加载。8 GiB 选项也不代表 Deck 有安全可用的 8 GiB 余量。

guest 分配器与纹理池常数必须按具体游戏版本定位，校验修改前指令和相关分配路径后才能制作配套补丁。不能直接套用其它版本的 `0x7300000` 或从 host 的 NVN 别名映射推断 guest 分配已经增加。

验收须使用合法自备的真实 HD 资源及配套代码补丁，核对画面变化、内存峰值、错误日志、移除回滚和无 Mod 基线。尚无此项通过证据，不增加硬件验收标志。

### SDK7 实机定位与配套预算实验

固定 1.6.0 原始指纹的独立代码补丁已完成生产 AOT：三模块完整重生成，1901 个生成文件一致，仅一个 C 单元改变。Deck 原版／变体／原版观测中，两个 NVN 池请求及实际贴图引用的容量为 115／256／115 MiB，其余请求大小和标志保持一致。

仅改池容量的变体未通过 3D 验收：原版前后均进入室外场景，变体加载时 `PlacementMgr動的` 请求 328 MiB 返回空指针，随后访问 `+0xd8`。只读分配返回观测确认成功／空指针／成功，总 guest 堆均为 3120 MiB；`OpenWorldStage` 父堆大小由约 356.5 MiB 降到 215.5 MiB，减少 141 MiB。容量读回通过不能代替加载验收。

新增默认关闭的 Linux SDK7 实验配置 `SAVAGEWIND_SDK7_HD_HEAP=1`：在每次标题启动、库版本确认后固定读取，为 GetInfo 6/21 的应用内存预算增加 160 MiB，配套上述池扩容。原 SetHeapSize 上限与地址范围继续约束实际请求；其他版本、平台和无效配置使用原预算。运行中修改环境不会改变本次预算。此项需与精确版本的代码 Mod 成套测试，尚未证明修复变体的 3D 加载或真实 HD 资源可用，不加入默认掌机启动器。

相关私有实机证据已逐成员核验：`botw-sdk7-pool-256-deck-20261114.tar.gz`，SHA-256 `b335109d6694d140581bf6d98aedb463185fa5804c557909577c0da9cb5b9d6e`。掌机临时诊断目录、测试缓存和隔离存档已清理；实验候选仅留作配套预算验证，原玩家数据与正式入口未变。
